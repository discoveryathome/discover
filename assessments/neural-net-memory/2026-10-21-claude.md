`MODEL.md` (the exact model), `discover/frontier.json`, `CONTRIBUTING.md` (packages,
picker, credit). All four questions are answerable from the files. One thing could
mislead: the current result has two layers. The authoritative table

say to read the trial package first, so a careful agent gets it right; a hurried one
would compare with the older table.

## Suggestions (don't affect grades)

- **Reconcile the trial into the authoritative table** (or have the picker read
  `candidates.json`), so a drawn row shows the best known value. This is the first
  thing a donor would hit.
- **Establish realistic-graph relevance,** as the pilot report asks: the workload graphs
  are analytic macro-op abstractions (`model-fidelity` assumption). An exporter from
  real PyTorch graphs, with parity checks, would let a better schedule mean something
  outside the model.
- **Compare with a modern solver** (Checkmate's MILP or Moccasin) on the same graphs, so
  "improves tuned baseline families" is measured against the strongest method, not
  only the included baselines.
- **To unpause:** commit a review capacity, get one independent verifier audit (the
  `verification` track), and reconcile the trial.
