### 1. Orientation: adequate (by reading)

The entry chain is `AGENTS.md` → `DISCOVERY.md` → `docs/LITERATURE.md`,
`docs/VERIFICATION.md`, `docs/SUBMISSIONS.md`, `results/summary.json`.

- **Problem:** clear. Four tracks (fixed linear maps, polynomial-basis GF(2^m)
  multipliers, 4×4 block-MDS design, complete AES S-box as a stretch), with the cost
  model (binary XOR, paid NOT; AND, XOR, total and depth as separate Pareto coordinates)
  stated in `AGENTS.md` and the README.
- **Current result:** findable, but framed as a claim about the pilot, not the circuits.
  `discover/frontier.json` states "four of six sessions advanced the literature-reconciled
  frontier", with metric `4/6`; the circuits themselves are in
  `research/agent-pilot-v2/review/current-frontier.json` and the report's table
  (Whirlwind M0 to (156,12), (157,11), (158,10), (166,9); M1 to (163,10), (164,9); AES
  MixColumns no advance). `DISCOVERY.md` points there.
- **Where help is wanted:** the catalogue and priority log answer it, but both say they
  apply "only to future local research, not an invitation to donors".
- **How to contribute:** `docs/SUBMISSIONS.md` is precise about what's accepted (both
  checkers, nondominated against the reconciled frontier, count-only claims resolved,
  candidate-specific adjudication). How a contribution reaches the project isn't stated:
  posting and PRs are off, and coordination is a local file.

Two things would mislead a fresh agent: the only message in `discover/messages.jsonl` is
the earlier calibration's "recommend postponement", and the catalogue and priority log
reflect that calibration rather than the later agent screen that passed. Not wrong, but
an agent has to reconcile them.

### 2. Coordination: weak

- **Spread: adequate.** A weighted catalogue (five tracks, six cards), drawn with the
  hub's seeded picker. With no channel, the draw can't see live claims.
- **Live state: weak.** No public channel: `AGENTS.md` says local coordination uses
  `discover/messages.jsonl` and "no messages are sent"; Discussions are off; Issues are on
  but unused; the manifest sets `post_messages` and `open_prs` to false. An agent can't
  tell what anyone else is doing.

### 3. Verification: adequate (covers: computation)

One authoritative record, `discover/frontier.json`, with pinned artifact hashes and a
declared `reproduce`. Run in a disposable copy, standard library only:

| Command | Result | Time |
|---|---|---|
| `python3 tools/fetch_optional_artifacts.py` | 2 hash-checked artifacts, 1 download from the pinned SBP commit, no upstream code run | 0.4 s |
| `python3 research/agent-pilot-v2/tools/verify_results.py` (the `reproduce`) | ok: 74 pinned files, 147 certificates, 294 fresh checker processes (both checkers), all results and metrics unchanged | 20 s (stated: 1 min) |
| `python3 -m unittest discover -s tests` | 10 tests OK | 1 s |
| `python3 tools/fetch_optional_artifacts.py --all` then `python3 tools/check_all.py` | ok: 391 certificates checked | 54 s |

`check_all.py` needs the `--all` fetch first; the README says so, but a first run
without it fails on a missing `sources/sbp/CITATION.cff`.

**Coverage.** The checks confirm integrity, exact function and gate costs (the script's
own scope line: "novelty is separately reviewed"). The frontier's headline is that
sessions advanced the *published* frontier, which rests on literature adjudication by
independent agents (`review/wave1-adjudication.json`, `wave2-adjudication.json`), not on
the check, and the record's evidence level is `author-checked`. External human novelty
review is outstanding, as the project says. So adequate.

### 5. Steering: adequate

Priorities are stated in one place (`discover/catalog.json`, revision 1, with

## Before donors arrive (suggestions; don't affect grades)

- **Unpausing** needs a review commitment: `review.per_week` (or `"surge"`), and
  `paused: false`. It's the maintainer's switch.
- **A public channel:** enable Discussions (the hub's board reads them) or state an
  issues convention, and set `post_messages` / `open_prs` so a Stage 1 listing can use them.
- **Update the catalogue and priority log** for the agent screen's result, and retire or
  supersede the calibration's "recommend postponement" message.
- **Frontier framing:** consider stating the circuit frontier itself (or a record table
  of instances), with the pilot's 4/6 as context, so the current result is the
  constructions rather than a session count.
- **Independent review:** the frontier stays `author-checked` until an independent rerun
  of the adjudications or an external expert's review.
